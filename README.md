# Граф денег

Локальный расчёт по трём предоставленным Parquet. Создаёт `nodes_roles.csv`,
`clusters.csv`, `top_nodes.csv`, `graph.json`, `robustness.csv` и
`completeness.md`; локальный viewer показывает
направленные связи, роль и объяснение найденного `gid`.

## Запуск

Требуется Python 3.9. Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python pipeline.py --data data --out out
```

Одна команда после установки зависимостей пересчитывает обязательные три CSV
и дополнительные артефакты в `out/`. Для просмотра из корня репозитория
запустите в другом терминале:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/viewer/`. Введите точный `gid` из CSV;
клик по соседнему узлу открывает его связи. Стрелки указывают направление
перевода. Библиотека Cytoscape.js 3.34.3 находится локально в
`viewer/vendor/`, поэтому CDN не нужен. `gid` ищется по строковому `id`, чтобы
сохранить точность 18-значного идентификатора в JavaScript.
Карточка показывает числовое обоснование и временные сигналы; при проверенном
ответе модели для одного из пяти первых узлов топа — дополнительную гипотезу.

Проверка:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Все проверки выполняются локально; GitHub Actions для репозитория организатора
недоступны.

Ключ API не нужен для обязательного расчёта. Для необязательных гипотез
кластеров скопируйте `cp .env.example .env`, заполните `OPENAI_API_KEY` и
`OPENAI_MODEL`, затем повторите команду расчёта. При ключе один вызов
[OpenAI Responses API со strict JSON Schema](https://developers.openai.com/api/docs/guides/structured-outputs)
формирует качественные гипотезы для восьми кластеров с несколькими seed;
второй — дополнительные тексты для пяти узлов с наибольшим приоритетом.
Остальные кластеры и карточки остаются детерминированными. Код проверяет
возвращённые `gid`, числовые метрики и осторожность формулировок. Ошибка API
оставляет исходные гипотезы/числовые карточки и печатает `LLM DEGRADED`.
`--no-llm` пропускает оба необязательных вызова. Секреты не записываются
в CSV и логи.

Используются pandas 2.0.3, pyarrow 17.0.0, NetworkX 3.2.1,
NumPy 1.26.4, SciPy 1.13.1, openai 2.48.0 и python-dotenv 1.2.1;
данные и стартер предоставлены организаторами.

## Критерии

Роль выбирается в порядке `coordinator`, `consolidator`, `distributor`,
`transit`, `terminal`, `peripheral`. Пороги и формулы — в
[`docs/ONTOLOGY.md`](docs/ONTOLOGY.md) §7 и [`docs/PLAN.md`](docs/PLAN.md) §4.
`terminal` возможен только при `depth < 4`; отсутствие выхода на глубине 4
считается обрывом наблюдения. Кластеры — взвешенный Louvain на неориентированной
проекции с seed 42; потоковые метрики и betweenness сохраняют направление.
Скоры — сила структурных признаков и приоритет проверки, не вероятность
правонарушения. Граф ограничен исходящими внутрибанковскими переводами июля 2026
от 5 000 KZT и четырьмя коленами; отсутствие ребра за границей выборки не
означает отсутствия перевода.

Временные сигналы считаются по отдельным переводам из `transactions.parquet`:
исходящий перевод отмечается, если за 1–2 дня до него был наблюдаемый вход;
синхронный вход — минимум два разных плательщика одному `gid` в один день;
всплеск — минимум три операции за день и не менее трёхкратного среднего числа
операций в день за 31 день июля. Это дополнительные признаки, а не доказательство
движения тех же денег. Их числа и даты есть в `nodes_roles.csv`, `why` топа и
карточке viewer.

Дополнительная детерминированная проверка отмечает в `evidence` циклы длины
2–6, цепочки A→B→C с минимум двумя переводами на каждом ребре и группы
из минимум трёх переводов по 5 000–6 000 KZT одному получателю в один день.
`cycle_count` и `repeat_chain_count` — число мотивов с участием узла;
`split_tx_count` — число переводов в подходящих группах у получателя.
`robustness.csv` показывает слабосвязные компоненты и потерю направленного
пути длиной минимум одно ребро от seed к оставшимся consolidator/coordinator после удаления первых
5/10/20 узлов по неизменному приоритету. Доля потерь считается от всех 81
seed, включая удалённые. Исходный набор ролей не пересчитывается.
`completeness.md` описывает границы выгрузки и следующий запрос аналитику.
Проверки выявляют кандидатов для разбора, а не подтверждают происхождение денег.

При росте до ~1 млн узлов NetworkX и точный betweenness станут узким местом:
понадобятся потоковое чтение, компактное представление графа и приближённый
betweenness с проверкой ошибки на подвыборке. Эта версия рассчитана на
предоставленные 2 248 узлов.
